# Plano (revisto): Destaques na home + Página de pesquisa (biblioteca) de pacotes

## Requisitos acordados
1. **Home**: mostra apenas os pacotes com `destaque: true` em `pacotes.js`; se nenhum marcado, mostra todos (fallback — home nunca fica vazia). Os 3 pacotes atuais começam marcados como destaque.
2. **Biblioteca** (`pacotes.html` nova): lista TODOS os pacotes com filtros **em tempo real**:
   - Tipo de viagem: Todos / Nacional / Internacional;
   - Alcance de data: intervalo livre **De / Até** — pacote aparece se **qualquer data de saída** (`inicio`) cair no período;
   - Botão **"Limpar filtros"**; sem filtro ativo → todos visíveis.
3. Home ganha link **"Ver todos os pacotes"** → `pacotes.html`.
4. Filtragem combinável (AND dos filtros ativos), pronta para receber novos filtros depois.

## Mudanças arquivo por arquivo

### 1. `pacotes.js` — novos campos (continua fonte única)
- `destaque: true|false` por pacote (os 3 começam `true`);
- `tipo: "internacional" | "nacional"` (campo obrigatório no schema novo; hoje os 3 são `"internacional"`);
- `inicio: "AAAA-MM-DD"` em cada item de `datas` (data-máquina do 1º dia; o texto exibido continua sendo o campo `data`). Valores conferidos: Assunção `2026-12-05` e `2027-01-15`; EUA/Lisboa `2026-11-12`, `2026-12-05`, `2027-01-15`;
- Cabeçalho de instruções atualizado (incluindo "como destacar um pacote na home").

### 2. `render-pacotes.js` — destaques + motor de filtros
- `renderizarCards()` (home): renderiza só `destaque === true`; lista vazia → renderiza todos (fallback). Markup do card inalterado.
- Novas funções:
  - `pacotesFiltrados(filtros)` — filtragem pura: tipo + período (bounds De/Até opcionais, comparação lexicográfica de datas ISO; datas sem `inicio` são ignoradas quando há período ativo);
  - `renderizarBiblioteca()` — lê o formulário, filtra, renderiza cards, contador com plural certo ("1 pacote encontrado" / "3 pacotes encontrados") e estado vazio;
  - `iniciarBiblioteca()` — renderização inicial + listeners `input`/`change` (tempo real) + botão "Limpar filtros".
- `renderizarDatas()` intocada (páginas de destino não mudam).

### 3. `estilo-cards.css` (novo, compartilhado)
Extrai do `<style>` do `index.html` o bloco **completo** dos cards: `.cards-container`, `.card`, `.card:hover`, `.card-img`, `.card h3`, `.card p`, `.btn-card`, `.btn-card:hover` (linhas 133–195). Sem colisão com `estilo-destino.css` (verificado — classes de card só existiam no index).

### 4. `pacotes.html` (nova página de pesquisa)
- CSS nesta ordem: `estilo-destino.css` (header/menu/rodapé prontos) → `estilo-cards.css` → `estilo-pacotes.css` (por último, para estender o card com o selo).
- Estrutura:
  - Header fixo igual às páginas internas (logo, menu **Home | Pacotes | Contato-WhatsApp**, hambúrguer) + script inline no padrão dos artigos (inclui mouseleave);
  - Faixa de título compacta (h1 "Nossos Pacotes" + subtítulo) com **`margin-top: 70px`** para compensar o header fixo (mesmo padrão do `.article-hero` em `estilo-artigo.css:93`);
  - Barra de filtros: select Tipo (Todos/Nacional/Internacional), date "De"/"Até", botão "✕ Limpar filtros";
  - Contador de resultados + `div.cards-container` — cards com a **mesma base de markup da home + selo discreto "Internacional/Nacional" só na biblioteca** (home preserva o visual atual, sem selo);
  - Estado vazio ("Nenhum pacote encontrado") com botão de limpar embutido; rodapé padrão;
  - Scripts: `pacotes.js` + `render-pacotes.js` + `iniciarBiblioteca()`.
